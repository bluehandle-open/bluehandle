# 蓝色手柄通信协议

手机端是服务端，电脑端客户端主动连接。

- Wi‑Fi：TCP，默认端口 8088（可在手机设置中修改）。
- 蓝牙：RFCOMM，服务名 `MyBluetoothApp`，UUID `00001101-0000-1000-8000-00805F9B34FB`。

蓝牙连接建立后，手机先发一行 ASCII 文本 `MyBluetoothApp\r\n` 作为握手。Wi‑Fi 方式没有握手。

## 报文格式

所有报文都是二进制，前两个字节是报文头：

```
| type (1B) | totalLen (1B) | body (totalLen - 2 字节) |
```

- `totalLen` 是整条报文的长度，包含报文头。按**无符号**字节解析。
- 手机端保证 `totalLen` 不超过 127。
- 电脑端遇到不认识的 `type`，应按 `totalLen` 跳过整条报文，**不要断开连接**。

## 报文类型

| type | 名称 | 方向 | 说明 |
|---|---|---|---|
| 0x02 | 按键 | 手机 → 电脑 | 已有 |
| 0x40 | 结束 | 手机 → 电脑 | 已有，手机主动断开前发送 |
| 0x41 | 心跳 | 手机 → 电脑 | 已有，每秒一次，无正文 |
| 0x50 | 文本输入 | 手机 → 电脑 | **新增**，语音输入使用 |
| 0x51 | 锁屏 | 手机 → 电脑 | **新增**，遥控器锁屏键使用 |

### 0x02 按键

```
| 0x02 | totalLen | pressType (1B) | keyCode (1B) × n |
```

- `pressType`：1 = 按下，2 = 松开，3 = 按下并立即松开。
- `keyCode`：Windows 虚拟键码，n 个即组合键，按顺序按下、逆序松开。
- 键码 0 表示空位，应忽略。自定义键位方案会用 0 补齐到 3 个键。

改版后新增使用的键码，电脑端需要能原样模拟：

| 键码 | 含义 | 使用位置 |
|---|---|---|
| 0x5B | 左 Win | 遥控器「桌面」发 Win+D |
| 0x5D | 右键菜单键 | 遥控器「菜单」 |
| 0x09 + 0x12 | Alt+Tab | 遥控器「切换窗口」 |
| 0xAD / 0xAE / 0xAF | 静音 / 音量减 / 音量加 | 遥控器 |
| 0xB0 / 0xB1 / 0xB3 | 下一曲 / 上一曲 / 播放暂停 | 遥控器 |
| 0x21 / 0x22 | PgUp / PgDn | 遥控器翻页、PPT |
| 0x10 + 0x74 | Shift+F5 | PPT 从当前页放映 |
| 0x42 | B | PPT 黑屏 |

媒体键（0xAD–0xB3）用 `SendInput` 时需要设置 `KEYEVENTF_EXTENDEDKEY`。

### 0x50 文本输入（新增）

```
| 0x50 | totalLen | flags (1B) | UTF-8 字节 |
```

- `flags` bit0 = 1：这段文本输入完后再按一次回车。
- 每条报文的 UTF-8 正文不超过 120 字节，且不会把一个字符拆到两条报文里。长文本会连续发多条，**只有最后一条可能带回车标志**。电脑端逐条输入即可，不需要拼接缓存。
- 正文可以为空，此时只表示按一次回车。
- 输入中文必须用 Unicode 方式，例如 `SendInput` 配合 `KEYEVENTF_UNICODE`，不能走虚拟键码，否则会受当前输入法影响。

### 0x51 锁屏（新增）

```
| 0x51 | 0x02 |
```

电脑端应调用 `LockWorkStation()`。用 Win+L 模拟按键会被 Windows 拦截，不会生效。

## 兼容性

旧版电脑端不认识 0x50 和 0x51。手机端在界面上提示这两个功能需要新版电脑端。
